A map of the Lean proofs for ForShor

What is actually proved about Shor's algorithm here, and where to find it in the code

VerifiedQC · October 2026

The number people quote about Shor's algorithm is a gate count. Gate counts are how the field argues about when factoring a 2048-bit RSA modulus becomes feasible, and almost every one of them is an estimate: a circuit design on paper, a cost model, a spreadsheet. The point of ForShor is that this number can be a theorem. The repository is a Lean 4 proof that a specific, fully compiled order-finding circuit is correct, and a second proof, about the same compiled object, that it uses O(n^(2+ε)) elementary gates. Both are checked by the same kernel, all the way down from a high-level gate language to a low-level abstract machine, with no sorry and no axioms beyond Lean's own three.#print axioms on the headline theorems reports only propext, Classical.choice and Quot.sound. Decidable side conditions are closed by decide +kernel, never native_decide. The one sorry in the repository is a test that the axiom audit rejects it.

If we had to pick the single most important thing, it is that the resource bound and the correctness proof are about one object. It is not hard to verify an idealised circuit, and it is not hard to estimate a realistic one; the gap between the two is where the surprises live. Here the circuit whose success probability is bounded is the circuit whose gates are counted.

Concretely, three theorems. Shor_correct says the ideal order-finding circuit, after classical continued-fraction post-processing, returns exactly the order r with probability at least κ / log(log₂ N + 1), that is Ω(1 / log log N).κ = 1/π² ≈ 0.101: Shor's per-numerator Fourier constant 4/π² times the 1/4 of the totient bound φ(r)/r ≥ 1/(4 · log(log₂ N + 1)). The exponent register has log₂(2N²) bits, the modulus register log₂(2N). The classical budget T bounds the convergent scan and costs no gates. This is the probability of getting r itself, not of landing in a good window. Shor_correct_approx_lowered says the same bound survives compilation, up to a factor of two, once the per-step precision η is set by a closed form in N.The lowering itself is exact; the only loss is the modular-exponentiation approximation. Holding it to half the ideal bound costs O(log n) extra work bits; at 2048 bits η ≈ 2⁻⁵³, about 105 extra work bits. shorPrecision is a closed form, so there is no existential constant a circuit builder would have to guess. And exists_shorGateCountBound says that for every ε > 0 there is a Toom-Cook arity k at which the compiled circuit uses at most C · n^(2+ε) gates, n the size of the modulus register. That count is an honest count of LowGate operations under an explicit cost model, not an abstract measure.shorOrderFindingGateCount is LowGate.gateCount shorGateCostModel of the compiled circuit, and shorGateRate ε n is just n^(2+ε). A companion theorem, shorGateCountBound_of_setup, gives any admissible Toom-Cook table the bound at its own exponent log(2k−1)/log k; a k = 2 table runs at about n^2.585. Both theorems are about one table used at every width, which is the right statement for an exponent and not a gate count at n = 2048.

The proof, layer by layer

The whole development is five layers deep, and they are best read top to bottom, which is also the order the proof goes in. The specification comes first: the vocabulary every statement is written in, and the contract the final object has to meet. Then the three subroutines, each verified on its own and each resting on the one before it. Then the assembly that proves Shor's algorithm correct. Then the cost of that assembled circuit, as a theorem. And finally the concrete instance that fills in every remaining choice and hands the framework the object it asked for.Every arrow is a real import between these folders, read from the Lean sources. The solid labelled arrows are the ones that carry the argument, and the label is the theorem or the vocabulary that crosses it; thin grey arrows are real structure that is not part of the story; the dashed ones come from Shared, a lemma library that is not a step. Click a layer to open it.

Each panel shows the folder's role in the argument, the statement that carries it, copied verbatim from the source with a link to the line, and what it rests on and feeds. The Lean statements are deliberately shown as they are, instance arguments and all: the parameters k and ops that appear in every subroutine theorem are the Toom-Cook table, which is why one proof serves every admissible table, and the qs that appears everywhere is the semantics the theorems are generic over.

What this site is

The proof is about 160 Lean files and 2,700 declarations in eight folders, which is more than anyone wants to read top to bottom. This page is a guide to it. The layer graph above is the outline: each block is a top-level folder, each arrow is an import between folders, and opening a block shows what that folder is for, what it rests on and what it feeds, and its key statements quoted from the source with a link to the file and line on GitHub. It is meant to answer questions like “where is Shor_correct stated, and what does it rest on?” without cloning the repository.

The mathematics and the design are in our paper, ForShor: Formal Verification of Shor's Algorithm in Lean 4 with Verified Resource Estimation (Suresh, Patel, Cao and Tao, 2026). The paper tells the story, and the layer graph is its outline in the code.The arrows are the imports between top-level folders, read from the Lean sources by scripts/gen_docs_graph.py. The quoted statements are verbatim copies of the declarations at the file and line shown.

Where to start. Shor_correct and Shor_correct_approx_lowered for correctness; exists_shorGateCountBound for the gate count; Framework if you want to know what the statements mean before reading the proofs; and Reference for the computable instance, the one lake exe forshor_emit prints as JSON.

Checking it yourself

The project pins Lean v4.36.0-rc1 and a fixed Mathlib revision, so the prebuilt cache applies. With elan installed: 

lake exe cache get               # prebuilt Mathlib oleans
lake build                       # the whole development
lake exe forshor_emit 2 2 15 0   # the reference circuit for (k, a, N, m), as JSON

The construction is generic in its Toom-Cook table: any table that passes four decidable side conditions inherits the correctness theorem and the gate-count bound at its own exponent. The README's Submitting a table explains how such a table is stated and checked.
