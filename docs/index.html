A Lean 4 formalization · Mathlib

Shor's algorithm, verified — gate count included.

ForShor is a machine-checked proof that Shor's order-finding circuit, built on fast Toom-Cook multiplication and compiled from a high-level gate language down to a low-level abstract machine, recovers the multiplicative order with the standard inverse-polylogarithmic probability — and that the whole compiled circuit uses only O(n^(2+ε)) elementary gates.

Results

What is proved

Three theorems and a trust base. Every statement below is taken from the repository's README; the proof map shows where each lives and what it depends on.

Correctness · ideal circuit

Shor_correct

The ideal order-finding circuit, after classical continued-fraction post-processing, returns exactly the order with probability at least κ / (log₂ N)⁴, where κ = 4e⁻²/π² ≈ 0.0548. The exponent register has log₂(2N²) bits, the modulus register log₂(2N), and the classical budget T bounds the convergent scan without costing a gate.

Correctness · compiled circuit

Shor_correct_approx_lowered

The same bound survives compilation to the low-level machine, up to a factor of two, once the per-step precision η is chosen as a closed-form function of N (shorPrecision). The lowering itself is exact; the only loss is the modular-exponentiation approximation, which costs O(log n) extra work bits — about 270 at 2048 bits.

Resource estimate

exists_shorGateCountBound

For every ε > 0 there is a Toom-Cook arity k for which the fully compiled circuit uses O(n^(2+ε)) elementary gates, n the modulus register size. The count is an honest count of LowGate operations under an explicit cost model, not an abstract measure. shorGateCountBound_of_setup gives the same bound, at its own exponent log(2k−1)/log k, to any admissible table.

Trust base

What the kernel checked

  • No proof uses sorry. The one occurrence in the repository is a deliberate test that the axiom audit rejects it.
  • #print axioms on the headline theorems reports only propext, Classical.choice and Quot.sound. Decidable side conditions are closed by decide +kernel, never native_decide.
  • The reference implementation is computable end to end: referenceProgramAt lowers to an executable LowGate circuit, and lake exe forshor_emit prints it as JSON.

Main theorem

The statement, read line by line

The inequality alone does not say much. These are the five pieces it is made of, as the README unpacks them.

  1. probability_of_success (Framework/Contract.lean) is ∑ o : Fin Q, r_found T verify o Q r · probMeas x o (evalC C ψ): the probability that the measured outcome, after classical post-processing, is exactly the order r. Not the probability of landing in a good window.
  2. r_found (Framework/Math/ShorDefinition.lean) is the 0/1 indicator that scanning the first T Q continued-fraction convergents of o/Q, keeping those whose denominator d satisfies a^d ≡ 1 (mod N), returns r.
  3. T is any classical budget with continuedFractionSearchBound Q ≤ T Q. It bounds the convergent scan, is not a circuit parameter, and costs no gates.
  4. κ = 4e⁻²/π² ≈ 0.0548.
  5. Registers and input. The exponent register has log₂(2N²) bits and the modulus register log₂(2N); the input is the ideal IdealOrderFindingInput: all registers clean, exponent register in uniform superposition.

The gate-count side has the same shape. ShorGateCountBound qs ε k hk ops says that for any work-width budget cWork there are C and n₀ such that, for every valid instance with n ≥ n₀ and every precision η whose extra bits fit the budget, shorOrderFindingGateCount … ≤ C · n^(2+ε) — where shorOrderFindingGateCount is LowGate.gateCount of the compiled circuit under shorGateCostModel.

Architecture

How the proof is put together

Left to right is dependency order. Framework is the specification every theorem is stated in; the three subroutines are verified independently; Shor assembles them; GateCount counts the result; Reference instantiates everything concretely. Each block opens its own graph in the proof map.

  1. FrameworkspecificationRegisters, the Gate and LowGate languages, QSemantics, the cost model, classical number theory, the correctness contract, and what makes a Toom-Cook table admissible.
  2. PhaseProductsubroutineThe recursive Toom-Cook phase-product compiler: interpolation algebra, table generation, compilation and lowering correctness. QFTsubroutineThe QFT split identity and QFT lowering correctness. ModularExponentiationsubroutineModular multiplication and exponentiation approximation bounds.
  3. ShorassemblyOrder-finding circuits, Shor_correct, and whole-program lowering correctness.
  4. GateCountresource estimateCounting bounds for the phase product, the QFT, and the complete Shor circuit.
  5. Referenceconcrete instanceTurns an admissible table into an executable circuit family; generic in the table rather than tied to one.

Shared is a lemma library over Framework vocabulary used by every subroutine folder; it imports nothing from them and is not a step.
