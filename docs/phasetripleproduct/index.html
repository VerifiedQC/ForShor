A map of the Lean proofs for PhaseTripleProduct

A recursive Toom–Cook construction for a three-register phase, and what is proved about it

Scope: read this first

This page is about a different primitive from the one in ForShor's order-finding circuit. PhaseProduct applies \(\exp(i\pi\varphi\,xz)\) to two registers and is what ForShor's modular multiplication is built from. PhaseTripleProduct (PTP) applies \(\exp(i\pi\varphi\,xyz)\) to three. ForShor's correctness and gate-count theorems do not use it, and nothing here changes them.

The suite is standalone: it uses ForShor's gate language, semantics classes and cost model, and STO's table language, but sits in the benchmark repository (ShorTableOptimization), where it is an interim fork not yet merged upstream. See where it lives.

A phase triple product multiplies a basis state by \(\exp(i\pi\varphi\,x\,y\,z)\), where \(x,y,z\) are the signed integers held in three \(n\)-qubit registers. Done directly, with a doubly-controlled phase for each triple of bits, it costs about \(n^3\) gates. The recursive construction is ForShor's PhaseProduct one with a third factor. Split each operand into \(k\) limbs; the product of three degree-\((k-1)\) limb polynomials has degree \(3(k-1)\), so its value at the limb radix is a fixed rational combination of its values at \(3(k-1)+1 = 3k-2\) distinct points. Evaluating the three operands at each point with a short program of additions, negations and shifts, taking one smaller phase triple product per point, and recursing gives \(O(n^{\log_k(3k-2)})\) gates for a fixed table: \(n^{2}\) at \(k=2\), \(n^{1.77}\) at \(k=3\), tending to \(n\).\(\log_k(3k-2)\) for \(k = 2,3,4,5,6\): \(2.000,\ 1.771,\ 1.661,\ 1.609,\ 1.547\). The PhaseProduct exponent \(\log_k(2k-1)\) is \(1.585,\ 1.465,\ 1.404,\ 1.365,\ 1.343\). The comparison is between the exponents of the two constructions, not between two ways of computing the same thing.

The table is the same object as in PhaseProduct: STO's Prog k, a straight-line program of addScaled, negate, shiftL, shiftR and phaseProduct i checkpoints, with its interpolation points. What changes is the point count (\(3k-2\) rather than \(2k-1\)) and what a checkpoint means: each is taken on all three operands. The suite verifies this at the gate level in ForShor's LowGate language, for whole banded policies, and states one theorem: for every checked policy and every width there is a circuit following the policy that acts as the specification operator on every clean state, with an exact gate census. Extensions give a controlled version, the \(O(n^{\log_k(3k-2)})\) gate count, operands of unequal width and a qubit count.

Below, the construction first as a flow, then the proof as a graph of layers, then the recursion itself as a figure, then the theorems, what is not claimed, and how to check it. Every block links back to the Lean source at a recorded line.

How one node is computed

The whole construction is one step, repeated. Given three registers and a width, the policy either stops at a leaf or picks a table; the registers are split into limbs, moved to each interpolation point by the table's program, a smaller phase triple product is taken there, and everything is undone. Each of the \(3k-2\) smaller products is the same problem at a smaller width, which is the loop on the left. Click a step for what it does and the Lean statement that carries it.

The proof, layer by layer

Read the graph top to bottom. A module may import only modules that come earlier in the suite's layer order (the blocks below group modules by role, so an arrow never points up the figure); the suite enforces the order with scripts/check_ptp_layers.py, and every arrow below is a real import read from the Lean sources by this site's generator (the dashed arrow into Harness is the exception: the harness writes a Lean file that imports the suite). The spine is Table → Values → Gates → Scan → ExactBoard → Surface. The mathematics (node_identity) comes before any gate. The recursion exists twice, over the conservative scan widths and over the exact widths, and the headline theorem is stated at the exact ones. Everything below Surface is an extension or a witness.

Inside PTP: one table, applied recursively

The layer graph does not show how the circuit is built. The figure below draws the reference policy of the benchmark, policies/ref_ptp_2048.json, at \(n = 2048\). Its four bands use \(k = 6, 4, 2, 2\); at exact widths the recursion goes \(2048 \to 375 \to 189 \to 96 \to 50\), using the first, third, third and fourth bands and then the leaf, so the \(k = 4\) band is never reached. The middle panel draws the \(k = 2\) table of the third band, which splits one product into four, and the right panel what happens to each.

One recursion level. \(\Pi^{(0)}\) turns \((x_0, x_1)\) into \((x_0, x_0+x_1)\); two phase triple products are taken, at \(p=1\) on \(r_1\) and at \(p=0\) on \(r_0\). \(\Pi^{(1)}\) moves the registers to \((x_0 - x_1,\ x_1)\), for \(p=-1\) and \(p=\infty\). \(\Pi^{(2)}\) adds \(r_1\) back into \(r_0\), restoring \((x_0, x_1)\). Each product has its own angle, \(\varphi\,c_t\), with \(c_t\) the interpolation weight of its point at the limb radix \(B\): for this table \(c = (B+B^2)/2,\ 1-B^2,\ (B^2-B)/2,\ B^3-B\), and node_identity says they combine the four products into \(\varphi\,xyz\). The arithmetic is shared by all three operands, so a table operation becomes three gates, one per operand.

Why this has to be checked. A table is trusted only through its contract: \(3k-2\) distinct valid points, each checkpoint consuming the next point in order with the registers holding exactly that point's values, and the program returning the registers to where they started. The fault witnesses show the conditions are load-bearing. Declaring the points in the wrong order is rejected by the contract; and evaluated anyway it applies \(B^3+3B^2-5B+1\) rather than \((B+1)^3\) at \(x=y=z=B+1\). Running the children one bit below the exact width gives a circuit that is provably wrong on a concrete state, because an intermediate value overflows and is then read by a child.

What is proved

Statements are quoted at the strength Lean proves them. Every row depends on at most the axioms propext, Classical.choice and Quot.sound, checked by scripts/PTPAxiomCheck.lean (34 theorems; re-run for this page on 2026-11-05 against ForShor 6d55ad9, all 34 reported kernel-checked with exactly those three axioms). The links go to the line in the source.

TheoremWhat it says

Surface		 For every checked policy \(P\), width \(n\) and three disjoint \(n\)-qubit registers there is a circuit following \(P\) at exact widths that acts as the specification \(\exp(i\pi\varphi\,x_0x_1x_2)\) on every clean state (operands fit signed \(n\) bits, workspace \(|0\rangle\)), with the exact-board gate census as equalities and a qubit upper bound. Vacuous at \(n=0\).

Values		 The weighted sum over the \(3k-2\) declared points of the products of the three operands' point values equals \(\varphi\,x_0x_1x_2\), for every admissible table.

Values		 The exact width is minimal: one bit fewer and some operand that fits \(n\) bits has a reachable register value that does not fit.

ExactBoard		 Existence of the recursion for every checked policy and width at exact widths, with correctness and the census.

Accept		 The acceptance rule without the ladder: every table chosen at every width the exact recursion from \(n\) reaches has \(k \le m\) and strictly shrinks the width.

Controlled		 Controlled PTP by masking one operand, on the clean subspace: \(2n\) Toffolis (\(n\) of them \(\dagger\)), \(n+1\) extra qubits, no extra rotations.

Asymptotic		 For a constant policy the constructed circuit has \(O(n^{\log_k(3k-2)})\) gates under shorGateResourceModel (ptp_gateTotal_bound for the exact-board count).

Unbalanced		 Operands of unequal width, by in-place sign-extension padding: \(+2(d_0+d_1+d_2)\) CNOTs, qubits \(\le 3n\) plus workspace.

QubitsTight		 The circuit touches at most \(3n + \texttt{ptpWsTD}\) distinct qubits; ptp_qubits_le_ptpQubits makes ptpQubits a proved upper bound at the scan rule.

Witness		 The headline theorem specialised to ForShor's concrete Model.qs: the hypotheses are satisfiable.

Planner		 Every output of the Lean planner, for every oracle and width, passes PTPPolicy.check; plan_ladder says its ladder is the oracle's.

What is not claimed

  • Not part of order finding. ForShor's circuit uses PhaseProduct. These theorems do not enter its correctness or its \(n^{2+\varepsilon}\) bound.
  • Clean states only. The state-level theorems cover the span of clean kets. Zero widths make them vacuous.
  • Controlled PTP is the masked construction. ForShor-style leaf control, where every leaf phase is controlled, is a different construction and is not proved here. In the masked statement the control is not constrained against the other registers; the degenerate case is the identity on the clean span.
  • The gate count is for a constant policy (one table at every width), as in ForShor, and counts rz + toffoli + x + h + cnot under shorGateResourceModel (Cuccaro adders, arbitrary-angle rotations). It is not a T count. The multi-band reference policy is verified for correctness and census, not given an asymptotic bound.
  • Qubits. The theorems bound LowGate.usedQubits, not the framework's qubitCount, which adds the Cuccaro/negation scratch cleanAnc; that scratch is not bounded for the recursive circuit. ptpQubits is loose by up to a factor \(k\) per level.
  • Unequal widths are padded, not handled by a native unbalanced node. Open: that node, the least width at which the wrapping semantics is correct, and the leaf-control variant.
  • No optimality statement. The planner's output is proved valid; nothing says the oracle's choices are good, and no table is claimed optimal. The benchmark scores PTP targets by the structural score only (below).
  • Review status. Audited by independent read-only AI reviewer passes, whose findings were fixed or narrowed (docs/ptp_gap_note/PTP_RIGOR_2026-11-04.md in the suite records them); no human review. The reference policy ref_ptp_2048.json was re-checked end to end for this page on 2026-11-05 against ForShor 6d55ad9: accepted at \(n=2048\) with exact widths, both kernel replays passing. The per-module trusted kernel replay (scripts/trusted) of the 2026-11-04 modules is recorded in that note as not re-run.

The benchmark targets

ShorTableOptimization asks for tables at \(k = 2,\dots,16\) for each of two modes. A table's score is arithmetic operations + 5 × parallel phase-product layers, a convention that trades size against depth. The benchmark prices PhaseTripleProduct structurally only: upstream has no gate model for it, so these scores are never T counts or gate counts. Checking it yourself

In a checkout of the suite, with elan installed. The suite builds against ForShor, so the first build compiles much of it (the fork's validation record for ForShor 6d55ad9: 8,753 jobs, about 10 minutes, 3.7 GB peak, on an M-series Mac): 

lake exe cache get
lake build TableGeneration.RecursiveCost.PTP TableGeneration.RecursiveCost.PTP.Main \
           TableGeneration.RecursiveCost.PTP.Controlled TableGeneration.RecursiveCost.PTP.Asymptotic \
           TableGeneration.RecursiveCost.PTP.StandardModel
lake env lean scripts/PTPAxiomCheck.lean     # #assert_axioms on the headline theorems
python3 scripts/check_ptp_layers.py          # layer order; no sorry / native_decide / axiom

To check a policy end to end, hand the harness a JSON file. It generates Lean, has the kernel decide the check and the exact-width acceptance rule, replays the kernel's report, and cross-checks the widths against a Python mirror. It exits 0 on accept and 1 on reject; the threshold_* and faulty_* policies are negative controls that must be rejected. 

python3 scripts/check_ptp_policy.py policies/ref_ptp_2048.json --target-width 2048 --widths exact --out ref_ptp.record.json
python3 scripts/ptp_exact_width.py policies/ref_ptp_2048.json 2048     # the exact and scan ladders, no Lean needed

This page's graph and figure are generated from the Lean sources by scripts/gen_ptp_site.py in the ForShor repository (--check fails if the data on disk is stale). The figure's table is executed by the generator, which also re-checks the node identity on it by exact arithmetic.
