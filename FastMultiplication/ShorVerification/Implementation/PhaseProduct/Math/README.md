# `Math/`

Pure mathematics — no register/framework dependencies (with the exception of
`Table_Generation/`, see below, which has its own README).

## `ToomCook.lean`

The interpolation algebra behind the compiler's phase-coefficient scheme,
stated abstractly (independent of the compiler's own `Point`/register types;
`Compiler/Coefficients.lean` bridges the two).

- **`Point`** — an interpolation point, either an integer (`.int`) or a
  reciprocal/fractional one (`.frac`, read as `1/c`).
- **`pointRow`** — the row a point contributes to the interpolation matrix:
  `z^j` for an integer point, `c^(m-1-j)` for a fractional one (so both kinds
  of point stay polynomial in the matrix).
- **`interpMatrix`**, **`GoodInterpolationPoints`**, **`listToFin`** — the
  interpolation matrix built from a chosen row function and point set, the
  statement that it's invertible (nonzero determinant), and the list-to-`Fin`
  adapter the two are applied through. These three **moved to
  `Framework/ToomCookTable.lean`** (`SUBMISSION_PLAN.md` S2.0), keeping their
  names: they are how a *submitted* point set's admissibility is stated, so
  they belong with the rules rather than the algebra. "Decidable in
  principle" is now decidable in fact — `Submission/Decide.lean` supplies the
  instance. Every invertibility and interpolation *proof* stayed here.
- **`interpCoeff`** — the actual interpolation coefficients for evaluating at
  radix `B`: `(radixRow B) · M⁻¹`. **`interpCoeff_correct`** is the key
  algebraic fact: summing `interpCoeff i * (value at point i)` reproduces
  `evalAtRadix` — i.e. these coefficients really do interpolate.
- **`weightedPointSum`**, **`phaseFactor`**, **`phaseScalarFromList`** — turn a
  coefficient/point-term pairing into the complex exponential phase scalar
  `exp(i·φ·coeff·term)`, and fold that across a list of points — this is the
  abstract shape of the phase a compiled phase-product circuit contributes.
- **`alternatingPoint`**, **`genFiniteInterpolationPoints`** — the canonical
  point sequence `0, -1, 1, -2, 2, …` and the first `m` of them; the pure-math
  counterpart of `Compiler/Coefficients.lean`'s `genInterpolationPoints`.

## `MasterTheorem.lean`

The scalar recurrence bound used to derive the compiler's asymptotic gate-count
result.

- **`shiftedMasterEnvelope k q M A B D`** — a natural-valued majorant `P` for
  a "shift-then-recurse" cost recurrence: `P(t) = A·(M + t/k) + B + q·P(t/k)`,
  `P(0) = D`. This is the general shape of "one level of compiled overhead,
  plus `q` recursive child calls at input size `t/k`".
- **`masterGeom q m`** — the geometric sum `1 + q + … + q^(m-1)`, i.e. how
  many total recursive calls accumulate across `m` levels when each level
  spawns `q` children.
- **`masterMixed q k m`** — the mixed geometric sum `k^(m-1) + q·k^(m-2) + …`
  generated by the *linear* (non-constant) part of the recurrence, i.e. how
  the `t/k` shrinking input size interacts with the `q`-fold branching.
