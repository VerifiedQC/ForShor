# Adversarial review of ENCODING_LEMMA.md

## Verdict: CORRECT-WITH-FIXES (no fatal or major defect found; four minor presentation or underspecification points)

I tried to break each of (a)-(f) and could not. The central claim holds: no nu_2 constant is needed, every pattern row has |alpha|<=2 and |beta|<=8k^2, and t<=C+1.

## Independently re-derived or tested

* Lemma 1 (a). I re-derived it by induction over Q, P, R. Each instruction's variable is attached to one instruction. Every occurrence is a time-ordered derivation chain, so an instruction occurs at most once on the chain. Source occurrences are copied from a state in which h_s has not appeared, so eta_s=0 before the add. No constants arise (Q and P need h>=1, a constant of size 1 only in x-bounds). I also simulated 3000 random Q/P/R/negation programs with k=2..4 and up to 7 additions, tracking occurrence lists and eta vectors. There were 0 violations of |O|<=2^alpha and of eta in {-1,0,1}.
* Lemma 2 (b). Re-derived. The strict inequality |G|<=m 2^{A_G}<=M 2^{A_G}<2^H 2^{A_G}<=2^B holds. The negative-B case is fine, since 2^{lambda-B} is an integer for lambda>=B. Ties are fine, gap 0 means the same cluster. H=C+2 gives 2^H=4*2^C>2^C+1, which also holds for C=0 (M=2, 2^2>2). The count m<=2^C+1 includes the anchor or target term.
* Lemma 3 (b). Re-derived. The anchor cluster has min<=0<=top. Hence any cluster below it has next-cluster minimum B<=0, which gives integer multiples of 2^B and the same |G|<2^B argument. Clusters above have all exponents >=H>0. Item (ii) follows. I also ran brute-force checks of both criteria against exact Fraction arithmetic: 240,000 random sums, C=0..3, M=2^C+1, H=C+2, exponents -9..9. There were 0 mismatches for zero and 0 for anchored integrality.
* Lemma E (c). Soundness holds. Adjacent constraints D_uv=g (0<=g<=H-1) or D_uv>=H give sortedness, because every label is >=0. They also give exact adjacent gaps, hence the cluster partition and, for the zero test, all relative values. For the anchored cluster they give absolute exponents, because the anchor is at constant exponent 0 and is linked to the other members by an exact-gap chain. So the integrality test of the anchor cluster, value=R*2^{lambda_min}, is a finite check that fixes lambda_min. This is exactly why nu_2 never becomes a constraint constant. I checked the report's example 2^{-x}+2^{-x}: accepted patterns are x=0 and x=1, and every pattern with x>=2 is rejected (g=2..H-1 gives 1/2^{...}, LARGE gives a nonzero lower cluster). That reproduces "integral iff x<=1". Equal exponents are harmless: ties are labeled 0 in any order, and completeness picks an arbitrary tie order. Identical forms give D identically 0, a trivial row. Completeness is immediate, since x* itself determines a sorted order and labels.
* Lemma 4 and the application (e). Arithmetic rechecked: H+k^2-1<=C+1+k^2<=7k^2<8k^2, and the scanner rows are at most 6k^2+3k<=8k^2 for k>=2. The small-integer-point lemma is applied to {x>=0: Ax<=b} with integer A,b, |entries|<=B. It makes no assumption about equality-implied growth, because vertices are bounded by Cramer's rule (t!B^t) whatever the equalities force. The Fibonacci remark is therefore consistent: exponential in t is below t!. S(t)=(t+1)t!B^t is increasing in t, so using t<=C+1<=6k^2 is legitimate.
* t<=C+1 versus t<=2C+1. The 2C+1 claim comes from SATURATION_REFINEMENT line 11 (an earlier case split with add exponent q and right-normalization exponent t counted as two variables). The later note SATURATION_AND_SINGLE_EXP_FPT section 3 shows, by parity under min(p,q)=0 with primitive Y_d and Y_s, that exactly one exponent variable is ever free per addition: Q (q>=1, t=0), P (p>=1, t=0), R (p=q=0, t>=0). Each addition costs >=1, so A<=C and t=A+1<=C+1. The draft is right. The 2C+1 figure is superseded and harmless (12k^2 still gives 2^{O(k^2 log k)}).
* (f) Fairness about the report. Report section 5.4 step 3 and Appendix B state integrality as "mu + nu_2(|A|) >= 0" per nonzero group. Appendix C.2 sets B=2MG+E+2k+10 with M=2^gamma+1 and G=gamma+2, so B has O(k^2) bits. The draft's description is accurate. The two encodings are logically equivalent as feasibility tests. In the report's encoding the group's lowest exponent mu is affine in x, so the valuation shows up as a constant. In the draft's encoding the anchor ties the position of the relevant cluster to 0 through adjacent gaps, so the valuation is evaluated inside the finite acceptance test. "Neither is a mistake" is fair. The draft's remark that nu_2(A) can reach about the number of terms (about 2^C, e.g. 1+1+2+4+...) is correct (the report's bound MG is a cruder upper bound), and 2^C is exponential in C=O(k^2), which is why the report's B has O(k^2) bits. One unverified statement: the draft's "2^{O(k^4)} by the sign-case route there". The report tables list "Joint sign cases 2^{O(k^4)}", which matches loosely, but I did not audit the report's total runtime.

## Defects (all minor)

1. Section 5, scanner rows: underspecified (minor). The draft does not state which rows are imposed. Fix: "For every instruction boundary (including the post-add, pre-right-shift peak of template R and the post-left-shift peak of template P), every row index i, and both r in {0,k-1}, impose each unrolled path value <= a (r=0) or <= a-d+k-1 (r=k-1)." The path-constant claim then reads: constant <= (number of additions and negations on the path) + (k-1 if r=k-1) <= C+k-1. Also state, for scanner soundness, that the unrolled affine path value equals the true width because (I) and invertibility hold for any x in P, so no right shift clips (SYMBOLIC_THRESHOLD section 4). As written this is only cited. The bound |beta|<=C+2k+d is loose but valid. The sharper value is |beta|<=C+d+k-1 (r=k-1) or C (r=0).
2. Lemma E.1 and Lemma 4 omit the x-bounds (minor). Templates Q and P carry h>=1 and R carries h>=0 (constant <=1, trivial). Add this to Lemma 4's list. It is not needed for soundness, since h=0 still gives a legal table, so no logical gap.
3. Section 2 target exponent bound e<k^2 is imported without a citation (minor). The source is SATURATION_AND_SINGLE_EXP_FPT section 4 (first 2k-1 points have dyadic exponent <=k, so entries have exponent <=k(k-1)). Cite it. I did not recheck the F2 point set itself.
4. Lemma 1 proof wording (minor). "Each of the two parts comes from a state after at most alpha-1 additions" is correct but should say "from the state before the current instruction". For templates P and R it should be explicit that the shift and the addition are two consecutive steps, and that only the addition increments alpha. Also the claim that nu_2 "never appears" holds for the constraint matrix. nu_2 and the cluster integers still occur in the acceptance test, which §4 correctly says. Section 0 says all x>=0 and "one variable per addition"; add "the template (Q/P/R) of each addition is part of the skeleton enumeration".
